# D：最终报告与采集设计

## 结论摘要

统一 `admission_cycle` 可行，但它只能是每条事实的规范化维度，不能成为把不同年份语义混在一起的页面标签。2026 表示来源明确声明的 2026 级招生录取周期。目录、国家线、校线、院线、专业/方向线、录取统计和行级成绩必须各自声明事实类型、来源年度语义和实体粒度，再独立映射到 2026；一种事实映射成功不代表其他事实也属于该届。

2023-2026 四届官方历史目录在南京大学、西安电子科技大学和深圳大学样本中可获得，证明年度目录可以建设；但载体、版式、培养单位结构和版本行为不统一。研招网当前目录请求没有显式年份，不能补历史。国家线和部分学校基本线有四届官方索引，学院/专业线需逐学院取证。深圳大学官方统计证明录取人数和初试 min/avg/max 可以在院系/专业粒度获得，但本次没有取得可复核的复试成绩和最终总成绩。

当前产品精确覆盖仍是：年度目录 0%，严格分型的五类分数线均 0%，六类录取统计均 0%。另有 2454/3420 = 71.7544% 的学校-专业-届次存在未严格分型的分数参考记录。全国招生组合没有四届权威全集，覆盖率不可计算。

本研究的可复核入口如下：

- [`b-source-depth-samples.md`](b-source-depth-samples.md)：代表学校、研招网、第三方和存档的逐条调查。
- [`c-full-coverage-measurement.md`](c-full-coverage-measurement.md)：当前产品四届精确分母、分子和全国口径边界。
- [`evidence/local-audit.json`](evidence/local-audit.json)：SQL、聚合结果、只读状态和数据库哈希。
- [`evidence/source-inventory.json`](evidence/source-inventory.json)：每个具体来源的 URL、定位、字段、粒度、限制、三维可信度和确定终态。
- [`evidence/coverage-statistics.json`](evidence/coverage-statistics.json)：机器可读覆盖统计。
- [`evidence/admission-cycle-contract.json`](evidence/admission-cycle-contract.json)：后续接入前应实现的机器规则。

## 年份归一

每条原始证据都保留 `source_year` 和 `source_year_kind`，不得只留一个通用 `year`。来源正文或官方附件明确写“2026 年硕士研究生招生目录”，可记为 `catalog_declared_cycle`；明确写 2026 年复试基本线或录取统计，可分别记为对应的声明届次。只有来源年度语义明确且目标实体映射确定，`mapping_status` 才能是 `confirmed` 并写入 `admission_cycle`。

以下值绝不直接映射：接口请求年、发布日期、采集时间、观察时间、存档捕获时间、只出现在 URL 中而正文未声明的年份。第三方 `planListV2` 的请求年仍是 `plan_request_year`，除非逐条响应及其原始官方依据证明其语义。分数年份只能映射分数事实，不能证明同届目录或录取。

`not_offered` 需要完整官方年度目录覆盖目标范围，并在名称/代码变化和多候选映射处理后仍确定缺席。查询为空、接口错误、页面下线、第三方无记录及未映射实体全部是 `unknown`。

## 采集与留证

采集分两层。证据层保存不可变原文：原 URL、HTTP 状态、最终 URL、内容类型、采集时间、SHA-256、来源声明年份的页码/表格/图片坐标定位。PDF 保存原文件和逐页文本/渲染 QA；SPA 同时保存稳定接口响应和页面路由；图片统计保存原图，OCR 仅产出候选值，人工复核后才进入规范事实。

规范层从证据版本生成事实，不覆盖原文。每条事实带 `source_id`、`document_version_id`、事实类型、原始值、规范值、实体粒度、映射状态和定位。官方最新有效版本优先于研招网，再优先于经逐条审核的第三方记录。权威性、可追溯性、实体匹配粒度分别存储，不合成一个平台分数。

访问策略按域名限速、缓存响应并支持断点续采。需要正常登录时可使用用户授权会话；遇到验证码、访问控制、403/429 或明确限流立即记录 `受限`，不绕过。外部失败是证据边界，不触发把其他来源值填充过去。

## 严格事实类型

分数至少分为 `national_score_line`、`school_score_line`、`department_score_line`、`major_score_line`、`direction_score_line`。每类继续保存总分、单科、A/B 区、考生类型、学位/学科类别和适用条件。学校基本线不能复制成所有专业线，门类参考线不能标成某校专业线。

录取分别保存 `admitted_count`、`initial_score_min/avg/max`、`retest_score` 和 `final_score`。统计表的聚合值与名单行是不同事实；没有复试成绩列时不得由初试或总成绩反推。计划人数、实际录取人数、推免、统考、调剂也必须独立字段，不能互相替代。

## 五层实体映射

映射按学校、专业、院系、方向、具体计划自上而下。学校使用官方代码和经核验别名；专业保留届次内代码与名称；院系保存来源代码、名称和当届组织版本；方向保存原始代码/文本；计划再加入学习方式、考试方式和专项属性。父层未确定或子层属性冲突时，状态只能是 `ambiguous`/`unmapped`，并保留所有候选及判定证据。

深圳大学样本已证明同一学校专业跨届会新增、删除和更名培养单位。掌上考研与研招网学校/院系 ID 不兼容。名称相似度只能召回候选，不能自动确认。粗粒度证据可以挂在学校、门类或专业层，但不得复制给多个方向制造伪精度。

## 版本、更正和调剂

文档按 `initial`、`correction`、`supplement`、`adjustment`、`superseded` 建链，保留 `published_at`、`retrieved_at`、`supersedes_version_id` 和有效状态。查询默认选同届最新有效官方版本，但审计可重放任意历史版本。补充通知只增加其明确范围，更正只替换被明确更正的事实；调剂目录/名单保留 `adjustment` 关系，不能覆盖一志愿版本。

下线官方页面优先寻找官方站点仍存附件，其次使用网页存档。成功使用存档时必须同时保存原 URL、存档 URL、捕获时间和内容哈希；捕获时间不作为届次。本次未成功取得存档的页面继续标为 `不可用`，不伪造 archive URL。

## 去重与隐私

文档先按内容 SHA-256 去重，再按来源 URL、发布时间和哈希建立版本。目录事实键包含届次、学校、院系、专业、方向、学习方式、考试方式、专项和文档版本；录取聚合事实键包含届次、学校、院系、专业、统计类型和文档版本。

行级拟录取材料只在确有必要时处理。解析环境使用本地未提交密钥对规范化后的行标识生成 HMAC-SHA256；密钥、姓名、原始考号和原始含个人信息的中间表均不得进入 tracked 研究产物。可提交的只有不可逆标识、专业、成绩、来源文档 ID 和页/行定位。发布前必须运行字段名与内容双重隐私扫描。

## 更新流程

1. 每年招生简章期发现新目录，保存初始版本并建立届次实体候选。
2. 目录发布后检查更正、补充、专项和调剂材料，维护版本链。
3. 国家线和学校基本线发布后先严格分型，再追踪学院复试细则。
4. 公示期优先留证短生命周期的学院通知和录取材料；受限即停止并记录。
5. 录取结束后采集官方聚合统计，分别核验人数和各成绩字段。
6. 每次更新只重算受新版本影响的规范事实与映射，保留旧版本可审计性。

正式接入前的质量门是：年份语义确认、事实严格分型、实体粒度不提升、原文与定位齐全、版本关系解决、隐私扫描通过。自动解析失败或多候选映射进入人工队列，不以空值或相似名称自动兜底。

## 来源优先队列

第一优先是已验证四届、字段完整且可自动采集的学校官方目录（南京大学、西电、深圳大学）和研招网国家线；第二优先是学校校线和学院官方细则；第三优先是学校官方录取统计长图的人工复核。国科大历史入口需要先完成四届 URL/响应和培养单位映射验证。掌上考研只保留逐条第三方补充，计划接口因缺年和 ID 不兼容不得作为目录主源。

本设计不修改现有数据库 schema、同步逻辑、UI 或导出，也不启动 ISSUE-032。实施时应另立接入任务，以机器契约为验收输入，并先在小样本影子数据集中验证，再讨论 schema 和产品呈现。
