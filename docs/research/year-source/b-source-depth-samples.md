# B：来源深度样本与证据分级

## 方法与样本

本阶段在不登录、不绕过验证码、不提高请求频率的前提下，验证公开页面、PDF 和现有第三方接口。样本覆盖东部综合性 985（南京大学）、南部地方综合性高校（深圳大学）、西部行业型 211（西安电子科技大学）和科研院所体系（中国科学院大学），并同时检查研招网与掌上考研。专业样本覆盖学硕 `081200`、`083500` 和专硕 `085400`、`085410`；学校层次、地区、院校类型、培养单位组织方式及学硕/专硕均有差异。

机器可读逐条判定见 [`evidence/source-inventory.json`](evidence/source-inventory.json)。每条来源只有一个终态：`可自动采集`、`仅人工可用`、`受限`、`无历史数据` 或 `不可用`。判定针对本次实际观察到的具体页面、接口或材料，不是对整个平台的一揽子评级。

## 确定发现

### 官方年度目录可以形成可靠切片，但没有统一载体

南京大学 2023-2026 四届目录均由研究生院年度文章发布 PDF，PDF 明示招生届次；四份文件分别为 62、69、68、67 页，SHA-256 已写入来源清单。目录包含院系、专业、方向、学习方式、学位类型、考试科目、拟招总人数及备注。2026 第 43 页经渲染核对，可读出计算机学院的 `081200`、`083500`、`085404`、`085405`、`085412` 及其方向、科目和人数。因此“文章声明年度 + 官方 PDF + 页码/哈希 + 确定实体”可以映射 `admission_cycle`。

西安电子科技大学目录也是年度文章加 PDF，但版式和字段排列不同。2026 附件第 6 页可抽取 `081200`、`085410`、研究方向、初复试科目、全/非全和拟招人数；四届文章索引连续存在。它可自动采集，但必须保留原附件、最终下载 URL、哈希及版面 QA，不应假设南京大学解析器可直接复用。

深圳大学使用公开 SPA 年度系统。实测系统可以从 2026 切换到 2023，结构化列表展示学院代码/名称、学位或学科类型、专业、学制和拟招生人数。`085410` 计算机与软件学院计划数由 2023 的 50 变为 2026 的 54；同专业培养单位集合也发生增删。`081200` 同样出现培养单位和计划变化。这是年度目录实体真实变化的直接证据，也证明 `school + major` 不能作为具体计划的唯一实体。

研招网当前 `yjfxs.do` 可返回院系、方向、学习方式、考试方式、考试科目、拟招人数文本和专项筛选，但当前代码和实测请求均没有显式年份参数。它只可作为“观察到的当前目录快照”，结论为 `无历史数据`；`fetched_at`、请求日期或 2026 年访问都不能把它写成 2026 届目录。

### 分数必须按发布口径严格分型

研招网历年分数线专题明确区分国家线和 34 所自主划线高校基本要求，并保留 2023-2026 四届链接。国家线可自动采集为 `national_score_line`，实体最多到 A/B 区、考生类型和学科门类；34 所索引最多证明学校级年度材料存在。两者都不能冒充学院、专业或方向复试线。

南京大学四届校级复试基本线官方文章连续存在，可自动采集，但其匹配粒度是学校/学科类别。2026 学院复试办法汇总页明确以学院官网最新通知为准；计算机学院样本原链接当前返回“无效的文章参数”。所以学院线、专业线、名单及成绩不能由校线推导，具体学院来源在本次样本中判为 `受限`。

掌上考研南京大学 `081200` 分数探针虽然四届各返回一行，但响应实际为 `raw_code=08`、`match_scope=category`，不是 `081200` 专业线。四届总分只能逐条作为门类参考线保存。其权威性低、接口响应可追溯性中等、实体粒度仅门类；这三个维度不能合并成一个笼统“平台置信度”。

### 录取统计与行级成绩是不同数据产品

深圳大学官方“历年录取数据”连续列出 2023-2026。年度统计以长图发布，表头包括录取人数、推免/统考人数、简章计划、实考、过国家线、复试线、实际复试、调剂人数、初试最高/最低/平均分和国家线。它能支持院系/专业粒度的录取人数及初试分数统计，但不含复试成绩和最终总成绩。因为数值在图片中，OCR 只能定位候选值，逐行仍须人工复核，结论为 `仅人工可用`。

本次没有取得可复核的官方拟录取名单、复试成绩表或最终总成绩表。南京大学学院通知样本已下线，网页存档 CDX 连接也失败。因此这三类字段的确定覆盖是零，结论是 `不可用`，而不是“学校未发布”。本阶段 tracked 产物没有姓名、原始考号或可逆个人标识。

### 第三方空结果和跨来源 ID 均不能证明缺席

掌上考研 `planListV2` 对南京大学 `081200` 的低量请求返回 2023=0、2024=3、2025=3、2026=3；南京大学官方 2023 完整目录却明确包含 `081200`。因此第三方查询为空必须是 `unknown`，不能形成 `not_offered`。掌上考研学校 ID `39` 与研招网学校 ID `368194` 不兼容，院系和计划 ID 也不能直接关联。该具体计划来源判为 `受限`。

只有完整官方年度目录在完成学校、专业、院系名称/代码变化处理后，才能把确定缺席写为 `not_offered`。如果存在名称变化、代码变化或多个候选院系，状态保持 `ambiguous` 或 `unknown`，粗粒度事实仍可保留但不得挂到更细实体。

### 历史入口和存档入口本身不是历史证据

中国科学院大学首页可见“硕士目录”“硕士公告”“历史数据”等入口，但本次没有取得可复核的 2023-2026 四届稳定响应，也没有完成培养单位到当前院系实体的映射。因此该具体来源判为 `受限`，不能因为菜单叫“历史数据”就宣称四届覆盖。

对南京大学已下线学院页面的 Internet Archive CDX 查询，本次分别出现 TLS/连接关闭和超时，没有获得快照。该次候选来源判为 `不可用`。以后若取得存档，必须同时保存原 URL、存档 URL、捕获时间、响应哈希和原页面声明的届次；存档捕获时间不是 `admission_cycle`。

## 实体映射判定

| 层级 | 可接受的确定键 | 主要风险 | 本阶段判定 |
|---|---|---|---|
| 学校 | 官方学校代码或经核验的名称/别名 | 聚合平台学校 ID 不兼容 | 南京大学样本可确定；跨平台 ID 需映射表 |
| 专业 | 届次内专业代码 + 名称 | 代码改名、专业并拆 | `081200/083500/085400/085410` 可作候选，不足以确定计划 |
| 院系 | 届次内院系代码 + 名称 + 学校 | 名称变化、同名中心、培养单位调整 | 深圳大学实测发生增删，必须按届版本化 |
| 方向 | 原始方向代码/文本 + 上级院系/专业 | 文本改名、方向重排 | 官方完整目录可确定；聚合来源需多候选 |
| 具体计划 | 上述键 + 学习方式 + 考试方式 + 专项属性 | 合并计划人数、非全/专项混写 | 只有字段齐全且来源年度明确才允许确定映射 |

名称相似度只能产生候选。自动确定映射至少需要学校和专业确定、院系在该届唯一、方向及学习/考试方式无冲突；否则保留原始证据并进入人工队列。任何粗粒度分数或录取统计都不得因为同校同专业而复制到所有方向。

## 阶段 B 结论

四届数据可以可靠归入统一 `admission_cycle`，但前提是每一种事实都由来源自身声明届次，并保持独立的数据类型与实体粒度。不存在一个来源同时稳定提供四届完整目录、全部分数类型、录取人数、初试统计、复试成绩和最终总成绩。可行路径必须组合学校官方年度目录、研招网国家线/索引、学院官方细则和少量官方录取统计；第三方只作为逐条保留的补充证据。

发布日、采集日、请求年和网页存档捕获日只能各自保存在对应时间字段。查询为空只形成 `unknown`。同届更正、补充、调剂和学院“最新通知”必须形成版本链，不能覆盖旧证据。
