# YAM 项目路线图（Roadmap）

> 目标：把 YAM 从“能跑的工程项目”变成“别人能安装、测试、理解、持续使用的本地考研择校工具”。
> 本文档是唯一权威的总路线图。日常迭代以它为准，`known-issues.md` 记录具体 Bug，`progress.md` 记录已完成里程碑。

---

## 1. 当前基线（2026-07-24 状态）

### 已具备的能力
- Tauri 2 + React + TypeScript + Tailwind + Framer Motion 桌面应用
- 专业选择、采集、工作区、筛选、排序、分页
- 院校视图 + 招生计划视图（双视图）
- 多专业合并展示 + 专业 Tab 多选
- 收藏、对比、导出（CSV / Excel / JSON）
- 趋势图 + 研究方向 + 考试科目 + 多年数据
- 后台采集 + 取消 + 进度 + 阶段徽章 + 日志折叠
- 登录状态管理（检查/刷新/清除）
- 任务栏图标（YAM 抽象几何标）
- 29 个已知问题已全部修复（ISSUE-022 已完成重新定义与闭环）

### 核心缺失
- **没有明确的应用入口**（开发、测试、分发）
- **采集和登录流程仍偏工程化**（需终端、依赖手动 cookie）
- **数据模型尚未完全围绕“招生计划 + 研究方向”统一**
- **测试主要是 CDP 脚本，缺少分层自动化和发布前验收矩阵**
- **发布产物不固定**（藏在 `target/release`，无安装包流程）
- 全量 TypeScript 检查仍有历史残留错误

---

## 2. 指导原则

1. **信息量优先分配空间**：表的信息比图多时，图要小；图的信息复杂时，图可以大（动态尺寸）。
2. **左侧约束信息栏保留**：作为信息锚点，不删除。
3. **保持 inline 展开体验**：不退化成掌上考研式的详情页跳转。
4. **状态机明确**：采集/登录/同步只用明确状态，不用多布尔拼凑。
5. **先入口、后功能、再体验**：没有明确入口前，不堆新视觉功能。
6. **可回归 > 新功能**：每次发布必须能通过固定验收矩阵。

## 3. 优先级分层（P0 / P1 / P2）

### P0（必须先做，否则无法测试和分发）
- 明确开发/测试入口（`desktop:dev`）
- 明确构建/分发入口（`desktop:build`、`desktop:build:nsis`）
- 固定发布产物目录（`release/`）
- 根 README 明确启动、构建、安装、数据库位置
- 端口说明统一（9223）
- ISSUE-022 重新定义方向并关闭

### P1（核心产品能力，必须在可分发后尽快完成）
- 内置登录向导（无需终端 `--login`）
- 原子启动锁 + 采集状态机（idle / running / completed / failed / cancelled） ✅
- 统一数据模型：专业 → 院校 → 院系所 → 研究方向/招生计划 → 年份数据
- 工作区信息密度持续优化（方向区分、折叠、按信息量分配空间）
- 分层测试：单元 + 组件 + Tauri E2E + 发布前验收矩阵
- 错误处理与恢复能力（所有外部边界都有清晰用户反馈）

### P2（增强与长期）
- 性能优化（虚拟列表、增量加载、数据库索引、导出大数据不阻塞）
- 安全与数据边界（cookie 本地、日志不泄露、来源可追溯）
- 高级分析（方向对比、风险标签、个性化筛选、趋势预测）
- 发布流水线 + 崩溃日志 + 自动更新
- 贡献规范与问题反馈模板

## 4. 阶段规划

### 阶段 1：可测试版本（目标：开发者/测试人员能启动验证）
- 增加语义化脚本
- 统一 CDP 端口文档
- 完善 README 启动说明
- 建立基础发布检查清单
- 修复 main.rs 注释中的 9222

### 阶段 2：可分发版本（目标：测试人员可直接安装）
- `tauri build` 能产出 NSIS `.exe` 和 MSI
- 固定 `release/` 目录结构（Setup / Portable / checksums / RELEASE-NOTES）
- 验证干净 Windows 环境 + WebView2
- 数据库路径和权限验证
- 版本号与 Git tag 规范

### 阶段 3：稳定采集版本（目标：采集无需工程师手工干预）
- 内置登录向导（LoginRequiredModal + 自动保存 cookie）
- 原子启动锁（AtomicBool）
- 采集五状态机 + 进度协议结构化
- 三阶段降级重试 + 心跳 + YAM_LOG 协议
- ISSUE-022 重新定义（专业状态：可采集 / 采集中 / 完成 / 暂无公开数据 / 接口不可达 / 需要登录 / 失败）

### 阶段 4：核心分析版本（目标：工作区成为择校分析核心）
- 专业/院系所/研究方向统一层级模型（稳定 source_department_id + plan_key 已贯通；独立实体拆表待补）
- 方向级比较 + 筛选 + 排序 ✅（真实计划行比较、方向关键词筛选、院系/方向排序）
- 多院校、多方向并行展开 ✅
- 趋势 + 分数线 + 收藏 + 导出增强 ✅（可信度展示、计划导出、方向/计划收藏及收藏页分区）
- 信息密度：方向为空有明确 fallback，同一院系所只显示一次

### 阶段 5：可维护产品版本（目标：可持续迭代）
- 单元测试 + 组件测试 + E2E 回归
- 数据库迁移 + 备份恢复
- Windows CI/发布流水线 + 三处版本一致性检查 + draft GitHub Release ✅；应用内自动更新留后续
- 本地崩溃/诊断日志 ✅；远程错误上报坚持用户明确同意后再接入
- 贡献指南 + Bug/Feature/PR模板 + 私密安全报告规范 ✅

## 6. 版本与发布规范

- 版本号：`MAJOR.MINOR.PATCH`
  - MAJOR：不兼容模型变更
  - MINOR：新功能
  - PATCH：Bug 修复
- 每次发布必须包含：
  - Git tag
  - 构建产物（Setup / Portable）
  - RELEASE-NOTES.md
  - 变更影响（数据库是否需要迁移）
  - 已知问题
  - 测试报告摘要
